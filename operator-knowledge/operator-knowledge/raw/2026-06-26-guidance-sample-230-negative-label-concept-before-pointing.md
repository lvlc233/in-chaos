用户对 230 样本候选引导做负向标注。

问题：

候选输出中说：

> 你把“访问过程中的计数”写成了“子树递归返回的数量”。

用户指出，这种表达容易让用户不明所以。

原因：

- “访问过程中的计数”和“子树递归返回的数量”是 agent 先命名出来的概念；
- 用户可能并不知道这些名词指什么；
- 用户也不知道自己伪代码里的哪一部分对应“子树递归返回的数量”；
- 用户可能只是随机探索写出了这段伪代码，并没有形成这些抽象概念；
- 如果 agent 先抛概念名词，后面再解释，用户仍然可能一头雾水。

更好的方向：

- 不要先输出一个概念名词；
- 应像人类老师拿着笔一样，指到用户代码中的具体位置；
- 标出“你这里做错了什么”；
- 再说明“你这里实际在做的是什么”；
- 从具体代码/表达出发，再抽象命名。

待后续整理：

- 对用户伪代码做反馈时，应先指具体行，再给概念；
- 概念名词必须绑定到用户原文中的位置；
- 不应假设用户已经理解 agent 提出的抽象分类。
