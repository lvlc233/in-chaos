用户补充两个点：

1. 会话过程记录做数据集准备的日常化

- 日常会话过程中，应持续记录可用材料；
- 这些材料后续可以作为数据集或训练/迭代素材；
- 不应等到专门整理时才开始收集；
- 交互中的真实问题、修正、反例、偏移、卡点，本身就是高价值数据。

2. 逆案例的需求

- 只给 agent 正向案例，会导致 agent 看到案例后只会模仿案例内容；
- 需要提供逆案例，说明什么情况不应该这么做；
- 逆案例的目的不是反对规则，而是防止 agent 把规则机械化；
- 例如：展示“好的提问”时，也要给“为了提问而提问”的坏例子；
- 展示“总结”时，也要给“过度总结、抢走用户注意力”的坏例子。

待后续整理：

- skill 迭代应同时收集正例与逆例；
- 每条行为规则最好配一个“应该做”和一个“不应该做”；
- 会话过程中的自然反馈应被日常化记录，作为后续改 skill 或建数据集的素材。
