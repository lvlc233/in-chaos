# 系统复杂度-信息熵-环理论

## 触发背景

写skill时cc输出的内容看不懂，感觉很恶心。具体症状：
- agent将背景介绍写入skill（不必要）
- 多余的emoji（✨等）
- 同义词翻译堆叠（"技能"·skill·）
- 过度解释/比喻套比喻（沉淀→结晶→解释结晶）
- 不可读

不仅仅是agent开发的问题，人类开发也会过度设计。是系统演变的一般性问题。

## 第一层：复杂度 = 信噪比问题

- 上述症状的共性：有效信息被噪音稀释，信噪比低
- 噪音来源：emoji、同义词堆叠、过度命名（后端→信息交互中心的存储与计算系统）、幻觉
- 幻觉不只是模型幻觉，人也会有："我以为..."的时刻，引入了不可由已有信息构建的概念（不存在或矛盾）

减熵手段：
- 去除功能无关符号
- 同字段非必要情况仅用一种语言表达
- 对人类过程性思考做概念提取
- 使用尽可能简单的语言精准表达某个概念

但熵不能无限降——降到极限只剩一个token，系统坍塌。存在最低维持密度以维持系统存在。

## 第二层：环结构

稳定系统必须形成闭环：
- 最小环：双节点互指（A→B, B→A）
- 环可以当节点嵌套
- 线性工作是环的局部放大
- 缺环 → 系统不稳定（某节点算力崩塌）

**React结构例子：**
- llm ↔ tool（执行），基本双节点环
- 对无思考能力模型：在llm→tool链路上拆分思考节点 + 表述节点 → 正当增节点
- 对有思考能力模型：无需拆分，原结构即可 → 再加节点 = 徒增复杂度

**判据：**

| 情况 | 操作 | 复杂度变化 |
|------|------|-----------|
| 节点负载 > 能力上限 | 拆分节点 | 增加，正当（避免缺环） |
| 节点负载 ≤ 能力上限 | 不拆 | 单体最优 |
| 冗余加节点（能力已覆盖） | 不该加 | 徒增无效复杂度 |

最优环 = 节点最少 + 关系最简 + 每个节点恰好饱和

类比：后端单体 vs 分布式架构

## 第三层：有效性 = 上下文域内定义唯一

- 欧拉公式有效因为e/i/π各指向唯一且已被定义的概念
- "1=? 展开为2+(-1)"无意义——数值等价但无语义环支撑
- e是自然常数不是元电荷——同一符号在定义明确的系统内才有唯一指向
- 定义是环上的局部切线

## 人机上下文域偏差

人与LLM的上下文域差异导致环对不上：
- 要么始终不成环（反复探索）
- 要么成环后没清理 → 超环
- 人跟人之间也会这样
