# 反馈质量最小测试设计

状态：draft / 测试设计  
日期：2026-06-26  
目标：在不急着改 algo-coach 的前提下，验证 `反馈质量 v0.1` 是否能迁移到未参与规则形成的新样本。

## 1. 本轮测试目标

只测试一个维度：

> 反馈质量。

具体看：

- 是否贴用户具体说法；
- 是否判断对错；
- 是否指出具体错点；
- 是否区分错误层级；
- 是否避免泛化肯定、包装式结尾和评分表感。

不测试：

- 引导方向；
- 收捻；
- 等待；
- 是否进入下一阶段；
- 最终教学效果。

## 2. 偏好形成集

这些样本已经参与 `反馈质量 v0.1` 的形成，不能再作为泛化证明：

- 102 层序遍历；
- 230 BST 第 K 小；
- 199 右视图。

它们包含：

- 原始用户思路；
- agent 拟输出；
- 用户好/不好标注；
- 用户修正理由；
- 正例/逆例。

因此称为：

> 偏好形成集。

## 3. 未见测试候选

从现有 records 中选择未参与反馈质量规则形成的样本。

### 候选 A：101 对称二叉树

类型：

- 递归关系方向对；
- 边界、返回值、对象/值比较有问题。

适合测试：

- agent 是否能说清“递归方向对，但返回值和边界没闭合”；
- 是否能区分核心递归关系与伪代码执行问题。

### 候选 B：148 排序链表

类型：

- 用户没有自然想到分治；
- 后续理解“找中点 + 拆分 + 合并”；
- 卡点在算法范式识别，而不是伪代码细节。

适合测试：

- agent 是否能反馈“你会局部能力，但没有组合成整体范式”；
- 是否能避免简单说“没想到分治”。

### 候选 C：234 回文链表

类型：

- 用户从数组双指针/栈思路切到链表中点 + 反转；
- 卡点在单链表访问方向限制。

适合测试：

- agent 是否能反馈“人类折叠直觉对，但链表访问方向限制没有处理”；
- 是否能区分 O(n) 空间直观方案和 O(1) 空间进阶方案。

### 候选 D：98 验证二叉搜索树

类型：

- 用户坚持局部三节点判断；
- 后来意识到祖先约束需要压缩成区间。

适合测试：

- agent 是否能反馈“局部父子关系判断不够，缺失祖先边界”；
- 是否能贴具体反例说明错点。

## 4. 本轮先选样本

建议先选：

1. 101 对称二叉树；
2. 148 排序链表；
3. 98 验证二叉搜索树。

理由：

- 101 测递归伪代码反馈；
- 148 测算法范式反馈；
- 98 测错误模型/反例反馈；
- 三者和偏好形成集不完全同型。

## 5. 输出生成方式

每个样本生成一版 `反馈质量 v0.1` 输出。

要求：

- 不做引导；
- 不问下一步；
- 不进入代码；
- 只反馈当前思路质量。

## 6. 人类标注方式

用户只标：

```text
好 / 不好 / 哪点有问题
```

可选标注点：

- 泛不泛；
- 啰不啰嗦；
- 有没有贴用户输入；
- 错误层级是否准；
- 是否把“没做”和“做错”混在一起；
- 是否有模板感；
- 是否需要总结句。

## 6.1 测试样本必须带用户原话

用户指出：如果测试样本没有用户原话，就无法判断输出是否真的“贴用户输入”。

修正：

- 每个未见测试样本应包含用户原话或近原文；
- 不能只用 records 里的总结性描述；
- 否则反馈质量测试会偏成“对摘要反馈”，而不是“对用户输入反馈”。

最小样本结构：

```text
题目：
用户原话：
已知卡点：
旧风格输出：
v0.1 输出：
用户标注：
```

## 7. 暂不做的事

暂不做稳定性多轮采样。

原因：

- 当前还在确认测试设计能不能工作；
- 先看未见样本能否暴露新偏好问题；
- 等标注方式稳定后，再做多轮稳定性观察。

## 8. 进入下一阶段的条件

如果 2-3 个未见样本中：

- 没有出现明显崩坏；
- 用户标注的问题主要是小修；
- `反馈质量 v0.1` 能够被进一步修正为 v0.2；

则可以考虑：

- 把 `反馈质量 v0.2` 写入 algo-coach；
- 或继续补一个维度的测试。

## 9. 未见样本 101 标注

输出方式：

- A：旧 algo-coach 风格；
- B：反馈质量 v0.1 风格。

用户标注：

- B 整体不错；
- 但有两个问题。

### 问题 1：空节点边界指代不清

原句：

```text
空节点边界没覆盖完整。两个都为空时应成立；只有一个为空时应失败。
```

问题：

- 用户不确定“空节点”指什么；
- “两个”指哪两个不清楚；
- 应绑定到用户函数参数：`duic(tree_left, tree_right)`。

修正：

```text
这里要先处理 duic(tree_left, tree_right) 接收到的这两个节点：
如果 tree_left 和 tree_right 都是 null，当前这一对镜像位置成立；
如果只有一个是 null，说明结构不对称，直接失败。
```

继续修正：

- 用户认为“这里说的是 duic(tree_left, tree_right) 接收到的这两个节点”不够自然；
- 更好的方式是直接把变量嵌进判断句。

更自然写法：

```text
在 duic(tree_left, tree_right) 里，如果 tree_left 和 tree_right 都是 null，说明这一对镜像位置成立；
如果只有一个是 null，说明两边结构对不上，应直接失败。
```

### 当前结果

用户反馈：

> 可以；pass了。

101 在当前反馈质量测试中通过，但附带两条修正：

- 指代清晰要自然嵌入变量；
- 低阶/已知小问题要轻处理，不要等权放进核心错误。

## 10. 未见样本 148 标注

输出方式：

- A：旧 algo-coach 风格；
- B：反馈质量 v0.1 风格。

用户反馈：

> 好。

B 版有效点：

- 贴用户原始思路：“沿着 next 往后找更小元素”；
- 判断它能排序，但更像链表版选择排序；
- 说明复杂度问题是 `O(n²)`；
- 指出真正缺口不是单个操作，而是把找中点、单节点有序、合并有序链表组织成分治结构；
- 总结为“局部工具有，但没有组织成分治排序整体结构”。

当前结果：

- 148 在当前反馈质量测试中通过。

## 11. 未见样本 98 标注

输出方式：

- A：旧 algo-coach 风格；
- B：反馈质量 v0.1 风格。

用户对 B 做负向标注。

问题句：

```text
你一开始说“父节点，当前节点和子节点就够，不需要爷爷节点、曾祖父节点”，这个判断不对。
```

用户认为：

- 用户后面已经意识到这个想法错了；
- agent 没必要再机械地说“你错了”；
- 重点是反馈当前理解变化，而不是给历史错误填对错表；
- 反馈不是“对错填写表”。

修正方向：

- 承接用户已自我修正的部分；
- 关注从“三节点模型”到“转折处 / 祖先约束”的理解变化；
- 历史错误只作为对照，不作为开头判错。

### 98 修正版进一步标注

用户认为修正版反馈质量本身不错，但指出：

```text
下一步要把这个路径约束稳定表达成上下界。
```

这句话有提前给答案的问题。

原因：

- 此时用户还没有提出“上下界”；
- 这正是需要引导用户自己抵达的地方；
- 直接说出上下界属于引导/答案边界问题；
- 不属于反馈质量本身的问题。

修正：

- 反馈可以停在“你已经从三节点判断，转向路径约束问题”；
- 不在反馈里提前给出“上下界”这个最终结构；
- 后续如果进入引导，再设计问题让用户自己想到如何表达路径约束。

### 当前结果

用户反馈：

> 嗯，pass。

98 在当前反馈质量测试中通过，但附带一条重要边界：

- 反馈质量只描述当前理解状态和已有问题；
- 不应提前给出下一步引导里的关键答案。

### 问题 2：已知小问题应轻处理

原句：

```text
最外层调用 duic(tree.left, tree.right) 后，也需要返回它的结果。
```

用户指出：

- 这属于之前说过的小问题处理方式；
- agent 需要识别；
- 低阶/已知漏写不要和核心问题等权。

修正方向：

- 放入“另外 / 小问题”；
- 或轻提醒一句即可。
