# 案例使用原则 v0.1

状态：draft / 从训练过程收捻  
日期：2026-06-26  
来源：algo-coach skill 改造训练过程

## 背景

在改造 algo-coach 的过程中，曾尝试把一个具体递归边界案例直接写入 `SKILL.md`。

用户指出：

> 案例是最危险的订正，尽可能不要使用案例，或者专门存储案例而非随意使用。

进一步解释：

> 我们本身就是要从案例中提炼和学习。直接给案例会过拟合，有无深度学习的副作用，所以需要十分谨慎。

## 核心原则

案例用于提炼规则，不用于直接注入主规则。

也就是说：

```text
案例 → 偏好标注 → 提炼行为规则 → 写入 skill
```

而不是：

```text
案例 → 直接复制进 skill
```

## 为什么不能随意把案例写进 skill

### 1. 容易过拟合

agent 可能学到的是案例表层形状，而不是背后的判断规则。

例如：

- 某个递归边界案例通过了；
- 直接写进 skill；
- agent 以后遇到类似结构时机械套这个例子；
- 但实际用户卡点可能不是这个例子本身。

### 2. 会制造浅层模仿

案例能让输出看起来更像通过样本，但不一定真的理解：

- 什么时候该给案例；
- 案例应该多具体；
- 是否会泄露答案；
- 是否会偏离用户原输入。

### 3. 会污染默认输出风格

主 skill 中的案例容易变成默认话术。

结果：

- agent 倾向于主动举例；
- 输出变长；
- 用户注意力被新案例带走；
- 原本的“贴用户输入”被削弱。

## 案例应该怎么用

### 1. 用作偏好材料

案例可以用于：

- 正例；
- 逆例；
- 用户标注；
- 失败观察；
- 规则修正来源。

### 2. 用作评测材料

案例适合进入测试集或偏好资源包，用来检验规则是否有效。

例如：

```text
同一用户输入
→ 旧 skill 输出
→ 新 skill 输出
→ 用户标注
```

### 3. 用于提炼行为约束

从案例中抽：

- 触发条件；
- 应做动作；
- 不应做动作；
- 边界条件；
- 副作用。

写进主 skill 的应该是这些行为约束，而不是案例本身。

## 什么时候可以用案例

可以用，但要谨慎。

适合：

- 用户明确卡住；
- 抽象描述无法推进；
- 需要验证某个边界；
- 用户要求“举个例子”；
- 案例来自用户自己的输入或当前题目，而不是额外引入新场景。

不适合：

- 只是为了让输出显得完整；
- 刚形成一个规则就把通过样本写进去；
- 默认每次引导都举例；
- 用新案例替代用户原输入。

## 写 skill 时的规则

主 `SKILL.md` 中优先写：

- 触发信号；
- 行为原则；
- 禁止项；
- 判断顺序；
- 边界条件。

不要写：

- 长案例；
- 通过样本原文；
- 可直接复制的话术；
- 某次测试刚 pass 的输出。

如果确实需要案例：

- 放到单独资源文件；
- 明确案例用途是评测/参考，不是默认输出模板；
- 主 skill 只写“必要时读取案例资源”。

## 当前对 algo-coach 的影响

`algo-coach` 主 skill 应避免内置具体算法案例。

当前更合适的写法是：

```text
除非用户卡住或需要验证，否则优先用用户自己的输入做引导。
```

而不是：

```text
遇到递归边界时，使用某个固定二叉树案例。
```
