## 1. 正向案例

### 1.1 小步输出 + 真实收捻

来源：

- `raw/2026-06-25-positive-case-small-output-with-real-convergence.md`

用户标注：

- 一点点输出；
- 有方案；
- 有展开案例；
- 最后能收敛到一起；
- 收捻是真的收捻。

可提取偏好：

- 输出不要一次性过多；
- 可以展开，但必须围绕同一焦点；
- 结尾应归并，而不是继续开分支。

### 1.2 102 引导正例：短指出 + 轻问题

来源：

- `raw/2026-06-26-guidance-sample-102-positive-rewrite.md`

用户标注：

```text
这表示替换这一层最后一个元素，不是加入。
你可以想想，怎么往一个数组中添加一个元素到尾巴中？
```

可提取偏好：

- 简单操作错误适合短指出；
- 用轻问题唤醒已有知识；
- 不需要长解释。

### 1.3 230 引导正例：先指代码，再解释

来源：

- `raw/2026-06-26-guidance-sample-230-positive-and-preference-resource-pack.md`

用户标注：

- “确实好很多”；
- 有效点是先指具体代码行，再解释这行实际在做什么；
- 再指出返回含义混乱；
- 最后用小问题聚焦 `return` 的含义。

可提取偏好：

- 不先抛概念；
- 先绑定用户原文；
- 概念要从用户写法中长出来。

## 2. 负向案例

### 2.1 为了提问而提问

来源：

- `raw/2026-06-25-algo-coach-feedback-questioning-without-purpose.md`

用户问题：

- agent 总是继续提问；
- 用户不知道为什么要回答这个问题；
- 有些问题像是为了提问而提问；
- 没有先面对用户输入给反馈。

候选规则：

- 提问必须有目的；
- 用户给出思路后，先处理思路，再决定问不问。

### 2.2 反馈感不足

来源：

- `raw/2026-06-25-algo-coach-feedback-correctness-and-importance.md`

用户问题：

- 算法题有标准答案；
- agent 应指出哪里对、哪里错、错的重要程度；
- 不能只追问。

候选规则：

- 算法学习场景中，正误反馈是基本功能；
- “不代替思考”不等于“不提供判断”。

### 2.3 102 负例：啰嗦 / 偏移 / 控制感

来源：

- `raw/2026-06-26-guidance-sample-102-negative-label.md`

用户问题：

- “别管 xxx 也别管 xxx”啰嗦；
- 真实问题是替换/追加和初始化，但引导偏到层数和数组子数组对应；
- “这一轮只检查一件事”有控制感。

候选规则：

- 引导要贴住当前具体错误；
- 减少排除式表达；
- 聚焦不能变成控制。

### 2.4 230 负例：先抛概念导致不明所以

来源：

- `raw/2026-06-26-guidance-sample-230-negative-label-concept-before-pointing.md`

用户问题：

- “访问过程中的计数 / 子树递归返回的数量”用户可能看不懂；
- 用户不知道自己代码哪一部分对应这个概念；
- 应该像老师拿笔一样，指出用户哪里做错了。

候选规则：

- 先指具体行，再解释实际行为，再抽象命名。

## 3. 交互节奏素材

### 3.1 连续性和聚焦性

来源：

- `raw/2026-06-25-interaction-pattern-continuity-and-focus.md`

核心：

- 好的问题应顺着用户当前注意力轨道；
- 不应在用户还在补充时抛新问题；
- 总结后立刻问新问题会分叉注意力。

### 3.2 等待作为对话动作

来源：

- `raw/2026-06-25-interaction-pattern-waiting-as-conversational-action.md`

核心：

- 人类对话有等待；
- 等待不是空白，而是给对方处理和补充的空间；
- agent 不应总在结尾追加问题。

### 3.3 扩散后不收捻

来源：

- `raw/2026-06-25-interaction-pattern-diffusion-without-convergence.md`
- `raw/2026-06-25-interaction-pattern-question-expansion-and-drift.md`

核心：

- 问题不是扩散本身；
- 问题是扩散后不梳理、不收捻；
- agent 内容扩张，而用户回复有限，未解决空间会堆积。

### 3.4 DFS 式回退

来源：

- `raw/2026-06-25-interaction-pattern-dfs-backtracking-for-deep-exploration.md`

核心：

- 深度探索会忘记起点；
- 需要像 DFS 一样在合适时候回退；
- agent 应帮助维护探索栈和主线。

## 4. 实验方法素材

### 4.1 概念到操作鸿沟

来源：

- `raw/2026-06-25-concept-to-operation-gap.md`
- `raw/2026-06-25-interaction-pattern-from-idea-to-usefulness.md`

核心：

- 概念不等于可执行能力；
- skill 不能只复述用户概念；
- 需要把概念转成触发信号、动作、反例和验证。

### 4.2 对比实验和稳定性试验

来源：

- `raw/2026-06-25-concept-operation-needs-comparison-and-stability-tests.md`

核心：

- 需要对照组；
- 模型输出有随机性，需要稳定性观察；
- 记录版本，方便之后比较。

### 4.3 单维测试和目标明确

来源：

- `raw/2026-06-25-experiment-method-one-dimension-at-a-time.md`
- `raw/2026-06-25-experiment-method-clear-target-per-test.md`

核心：

- 每轮只测一个维度；
- 这样目标明确，结果更容易解释。

### 4.4 条件测试和正交测试的区分

来源：

- `raw/2026-06-25-experiment-method-independent-vs-conditional-tests.md`

核心：

- “在反馈达标基础上测引导”是条件测试；
- 正交测试不能建立在另一个维度达标的前提下。

### 4.5 方法校准 vs 正式测试

来源：

- `raw/2026-06-26-experiment-method-calibration-vs-formal-test.md`

核心：

- 当前仍是实验方法校准；

## 10. 术语修正：偏好形成集

用户指出：102、230、199 这种已被标注并用于形成规则的样本，本质是偏好，不只是训练数据。

采用术语：

- **偏好形成集**：输入 + 输出候选 + 用户偏好判断 + 修正理由；
- **未见测试集**：未参与规则形成的新样本，用来观察迁移；
- **偏好资源包**：整理正例、逆例、修正理由和边界条件。
