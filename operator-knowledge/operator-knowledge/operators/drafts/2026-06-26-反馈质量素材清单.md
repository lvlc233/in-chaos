# 反馈质量素材清单

状态：draft / 素材清单  
日期：2026-06-26  
用途：为 algo-coach 的“反馈质量”维度收集正反候选，不直接写规则。

## 本维度只看什么

只看 agent 是否能清楚反馈：

- 用户思路对不对；
- 哪些地方对；
- 哪些地方错；
- 错误重要程度；
- 错误类型是核心思路、边界、状态设计、递归组织，还是实现细节。

不看：

- 引导方向；
- 收捻；
- 等待；
- 术语负担；
- 最终教学效果。

## 候选素材 1：102 层序遍历

来源：

- `records/2026-06-24-binary-tree-level-order-traversal.md`

用户状态：

- 核心思路正确：递归携带 `layer`，二维数组按层存储；
- 主要错误集中在实现细节：
  - `array[layer][-1] = tree.val` 是覆盖，不是追加；
  - 新层条件不应是 `layer > len(array)`；
  - 从 `layer = -1` 开始会让判断错位；
  - 左右孩子都应接收 `layer + 1`。

反馈质量标注：

- 应判定：整体思路对；
- 错误类型：实现细节 + 边界表达；
- 重要程度：
  - `[-1] =` 属于具体操作错误；
  - 新层条件属于边界/初始化错误；
  - 不是核心算法方向错误。

可用作：

- 正向反馈样本：如何在“整体对，但细节错”时反馈；
- 反向风险：如果 agent 把它说成整体思路错，会过度打击；如果只问问题，又反馈不足。

### 102 拟输出 A 负向标注

用户认为反馈质量拟输出 A 不太好，主要是结尾啰嗦。

问题片段：

```text
所以这题不是“递归方案错了”，而是“层数组的创建和追加动作没写稳”。

当前距离完整逻辑已经很近：把新层创建、尾部追加、左右孩子传 layer + 1 这三个细节补上就可以闭合。
```

标注：

- 前面已经说过整体思路对、问题在实现细节；
- 结尾再次解释显得重复；
- “距离完整逻辑已经很近”这类总结不是必要信息；
- 反馈质量应更紧，避免包装式收尾。

### 102 拟输出 B 正向标注

用户反馈：

> 可以。

有效版本：

```text
整体思路是对的。

你抓住了核心：递归时带 layer，把节点值放进二维数组对应层。

主要问题是实现细节：

1. array[layer][-1] = tree.val 是覆盖最后一个元素，不是追加。
2. 新层创建条件要覆盖 layer = 0, array = []，所以 layer > len(array) 不行。
3. 如果从 layer = -1 开始并先判断，根节点会落在错误层级。

这几个是代码表达问题，不是算法方向问题。
```

偏好：

- 先定性；
- 再列具体问题；
- 末尾定性句也可省略；
- 不做包装式总结。

进一步修剪：

- 用户指出“不在算法洞察/不是算法方向问题”这一类末尾定性不需要；
- 前面已经说“整体思路是对的”和“主要问题是实现细节”，因此末尾再定性仍有重复感；
- 更好的版本可以停在具体错点列表。

## 候选素材 2：230 BST 第 K 小

来源：

- `records/2026-06-20-kth-smallest-element-in-a-bst.md`

用户状态：

- 核心洞察逐步形成：BST 中序遍历是升序，访问到第 `k` 个就是答案；
- 主要错误在代码组织：
  - 想用额外链表，后来知道不必要；
  - 把中序遍历中的共享计数，写成了递归返回值计算；
  - 边界写成 `node.left == null`，会跳过没有左孩子但自身需要访问的节点；
  - 尚未完整处理“找到答案后提前停止”。

反馈质量标注：

- 应判定：核心方向已对，但递归组织还没稳；
- 错误类型：递归状态设计 / 返回值含义混乱；
- 重要程度：
  - “共享计数 vs 返回值”是核心代码组织问题；
  - `node.left == null` 是边界判断错误；
  - 额外链表是空间优化问题，不是正确性错误。

可用作：

- 正向反馈样本：如何区分“算法洞察已对”和“伪代码结构不对”；
- 反向风险：如果只说“中序遍历就行”，会忽略用户真正卡在递归组织。

### 230 拟输出 A 局部修正：边界解释不够好

用户指出：

```text
if node.left == null: return num 这个边界不对。
没有左孩子不代表当前节点不用访问；统一边界应该看当前 node 是否为空。
```

这段解释不够好，可能需要一个简单总结。

更清楚的方向：

```text
递归停止条件应该是“当前没有节点可处理”，也就是 node == null。
node.left == null 只说明左子树为空，但当前节点本身仍然要被访问。
```

可提取偏好：

- 解释边界错误时，要指出“停止条件到底应该对应什么对象”；
- 对树递归来说，停止的是空节点，不是某个孩子为空。

### 230 反馈偏好：需要一句总述

用户建议补一句：

```text
总的来说，你现在 xxx，但是还有 xxx 的问题。
```

作用：

- 先告诉用户当前整体状态；
- 同时说明已对部分和剩余问题；
- 再进入具体错点会更清楚。

候选表达：

```text
总的来说，你已经抓住了“中序遍历计数”这个方向，
但递归函数里“什么时候计数、return 返回什么、何时停止”还没有分清。
```

位置修正：

- 用户认为这句可以放在最后面；
- 先列具体问题，再用这句话收束；
- 对 230 这种多点伪代码问题，结尾总述比开头总述更自然。

## 候选素材 3：199 右视图

来源：

- `records/2026-06-24-binary-tree-right-side-view.md`

用户状态：

- 核心方向成立：右侧优先 DFS，每层首次记录；
- 伪代码存在多个问题：
  - 遍历顺序命名不准确；
  - 记录对象写成 `tree.right`，实际应记录当前节点；
  - 缺少空节点边界；
  - 递归丢失 `layer`；
  - “可替换数组”与首次写入不覆盖矛盾；
  - 示例中右节点编号笔误。

反馈质量标注：

- 应判定：算法方向对，伪代码表达未闭合；
- 错误类型：
  - 记录对象写错、丢失 layer、缺空节点边界属于正确性问题；
  - 遍历顺序命名和示例笔误属于表达问题；
  - “可替换数组”属于规则语义矛盾。
- 重要程度：
  - 记录当前节点、传递 layer、空节点边界是核心伪代码问题；
  - 命名和笔误是次级问题。

可用作：

- 正向反馈样本：如何在同一方案中区分多类错误；
- 反向风险：如果把所有问题等权列出，用户不知道先修哪个。

### 199 拟输出 A 负向标注：开头太泛

用户指出：

- “整体方向是对的”太模糊；
- “你已经抓住了 xxx”也容易变成泛化模板；
- 用户不论说什么，agent 都可以这么说；
- 这类表述不够贴用户输入。

偏好修正：

- 先就用户具体说法判断对错；
- 再总结整体状态；
- 不要用泛化肯定句开头。

更好的方向：

```text
你说“不能只沿 right 走”，这个判断是对的。
你说“右优先遍历，每层第一次记录”，这个规则也是对的。
但你伪代码里当前层写的是 tree.right，这和“记录当前访问节点”的规则不一致。
```

### 199 拟输出 B 修正：需要结构化对/错

用户反馈：

- 方向合理，但可以更好；
- 可以结构化为“你说得对的地方有……”；
- 后面再说“错误的地方”；
- 注意只写错误，不写“还没有做的地方”；
- “还没有做的地方”属于引导，不属于反馈质量；
- 需要一句总结；
- “另外”部分可以保留，用来放命名不准确、笔误等次级问题。

候选结构：

```text
你说得对的地方有：
...

错误的地方是：
...

另外：
...

总结：
...
```

### 199 拟输出 C 负向标注：结构化过度

用户反馈：

> 这一版有点死死的感觉。

问题：

- 严格使用“对的地方 / 错误的地方 / 另外 / 总结”后，模板感变重；
- 虽然结构清楚，但不像自然反馈；
- 结构化不能机械化。

修正方向：

- 保留对/错/次级问题/总结的逻辑；
- 但表达上可以更自然；
- 不一定每个部分都用显式标题；
- 反馈应像人类老师在看方案，而不是填评分表。

### 199 自然结构版暂时可用

用户反馈：

> 还行，先这样子就。

有效方向：

- 保留对/错/次级问题/总结的逻辑；
- 但不用硬标题；
- 用自然段表达；
- 贴用户具体说法；
- 重点指出“记录谁”和“是否覆盖”两个对齐问题。

偏好：

- 结构化要隐含在表达里；
- 不要让反馈像填表。

## 候选素材 4：101 对称二叉树

来源：

- `records/2026-06-20-symmetric-tree.md`

用户状态：

- 核心思路正确：将人眼对称转换成两节点镜像比较；
- 伪代码问题较多：
  - `tree_left == tree_right` 可能误比较对象而不是值；
  - 空节点情况不完整；
  - 递归结果没有用 `and` 合并；
  - 失败分支没有立即返回；
  - 最外层没有返回辅助函数结果。

反馈质量标注：

- 应判定：递归方向对，返回值/边界处理错；
- 错误类型：
  - 辅助函数状态设计正确；
  - 返回值传播和边界顺序是核心逻辑问题；
  - 对象比较 vs 值比较是具体实现语义问题。
- 重要程度：
  - 不返回递归结果会让算法整体失效；
  - 空节点边界会导致错误判断或报错；
  - 值比较问题依语言而定，但必须说清。

可用作：

- 正向反馈样本：如何告诉用户“思路对，但伪代码无法正确返回结果”；
- 反向风险：如果只追问边界，用户可能不知道整体结构其实已经成立。

## 当前小结

反馈质量不是简单说“对/错”。

更细的标注维度是：

```text
整体方向是否对
核心洞察是否对
当前错误属于哪一层
哪些错误影响正确性
哪些只是表达/实现/命名问题
用户应该知道自己离完整解还有多远
```

## 当前缺口

还缺：

- 原始对话级别的正负输出对照；
- 用户明确标注“这段反馈好/不好”的更多材料；
- 对“反馈太多导致压迫感”的负例；
- 对“反馈太少导致不知所措”的负例。
