# 引导方向 v0.1

状态：draft / 从样本中暂时收捻  
日期：2026-06-26  
来源：algo-coach 交互模式校准过程

## 背景

最初问题是：agent 在算法学习中容易“为了提问而提问”。

后续校准发现：问题不是不能提问，而是需要根据错误类型选择不同强度的引导。

引导不应统一套模板，而应先判断用户当前卡点是什么类型。

## 当前分流规则

### 1. 核心状态 / 概念问题

适用：

- 用户的主方向对；
- 但某个状态、变量语义或概念角色混乱；
- 这个混乱会影响后续流程正确性。

做法：

1. 指出下一步看什么；
2. 说明为什么这个点优先；
3. 让用户检查一个具体表现。

例子：207 课程表中的 `array`。

有效表达：

```text
下一步先看 array 的含义。
原因是：它不是变量命名问题，而是整个流程的状态问题。
如果 array 表示“所有学过的课”，旧课程会一直留在里面；
如果 array 表示“本轮刚学完、等待处理后继的课”，处理完这一轮后就应该替换。

你可以先看：array 里的课程，在下一轮还会不会被重复当成“刚学完的课”使用。
```

注意：

- 不要直接塞完整替代方案；
- 不要强控制用户“这一轮只……”；
- 要给优先级理由。

### 2. 简单操作 / 表达错误

适用：

- 用户核心思路对；
- 错误在简单操作、语法表达、API 使用或小实现细节；
- 用户很可能知道相关知识，只是表达错或写错。

做法：

1. 短指出错误；
2. 用轻问题唤醒已有知识。

例子：102 层序遍历中的：

```text
array[layer][-1] = tree.val
```

有效表达：

```text
这表示替换这一层最后一个元素，不是加入。
你可以想想，怎么往一个数组中添加一个元素到尾巴中？
```

注意：

- 不要长篇解释；
- 不要抽象到另一个问题；
- 不要用“别管 A / 别管 B”制造啰嗦感。

### 3. 结构组织 / 递归状态错误

适用：

- 用户理解了大方向；
- 但伪代码里把不同递归组织方式混在一起；
- 问题出在返回值、共享状态、递归函数职责等结构设计上。

做法：

1. 先指用户具体代码行；
2. 解释这行实际在做什么；
3. 指出其中一个含义混乱点；
4. 用小问题让用户检查关键状态或返回值。

例子：230 BST 第 K 小中的：

```text
left_num = cout(new_num, node.left) + 1
```

有效表达：

```text
先看你这行：
left_num = cout(new_num, node.left) + 1

这行实际在表达：
左子树处理完后，把左边返回的数量 + 1，当成当前节点的位置。

问题是：后面你又用 return node.val 返回答案值。
这样同一个 cout 函数一会儿像是在返回数量，一会儿像是在返回答案。

你可以先检查：cout 这个函数，每次 return 的到底应该是什么？
```

注意：

- 不要先抛“访问过程计数 / 子树递归返回数量”这类抽象概念；
- 概念名词必须绑定到用户原文里的具体位置；
- 先拿“尺子”指代码，再命名。

### 4. 用户明确省略的简单细节

适用：

- 用户明确说某部分“我知道，只是懒得写 / 省略了”；
- 该部分确实是低阶简单细节；
- 不影响当前核心思路校准。

做法：

- 放行；
- 最多轻提醒；
- 不机械追问。

例子：

102 中用户说明初始化判断自己知道，只是懒得写。

注意：

- agent 要区分“用户不会”和“用户省略”；
- 不要为了完整性抓住低价值细节不放。

## 反例模式

### 1. 先抛概念

```text
你把访问过程中的计数写成了子树递归返回的数量。
```

问题：

- 用户可能不知道这些概念指什么；
- 用户不知道自己代码哪一部分对应这个概念；
- 增加解码成本。

### 2. 模板化排除

```text
先别管 A，也先别管 B，这一轮只检查 C。
```

问题：

- 容易啰嗦；
- 有控制感；
- 不像引导，像任务分配。

### 3. 引导偏移

102 的真实问题是“替换 vs 追加”，但引导转到“层数和数组第 n 个子数组的关系”。

问题：

- 看似相关，但没有贴住用户当前错误；
- 用户会感觉 agent 没有看懂自己到底错在哪。

## 当前结论

引导方向不应是固定话术，而应根据错误类型选择强度：

```text
核心状态错 → 给理由 + 聚焦检查
简单操作错 → 短指出 + 轻问题
递归结构错 → 指代码 + 解释实际含义 + 检查返回/状态
用户明确省略 → 放行
```

## 待验证

- 是否适用于更多算法题；
- 是否能稳定减少机械追问；
- 是否会导致 agent 过度判断用户“已经懂了”；
- 是否需要为每种错误类型补更多正例/逆例。
