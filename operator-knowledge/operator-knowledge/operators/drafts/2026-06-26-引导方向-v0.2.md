# 引导方向 v0.2

状态：draft / 未见样本测试后修正  
日期：2026-06-26  
来源：`引导方向 v0.1` + 未见样本 101 / 148 / 98

## 背景

`引导方向 v0.1` 来自 207、102、230 三个偏好形成样本。

随后用未见样本做最小测试：

- 101 对称二叉树；
- 148 排序链表；
- 98 验证二叉搜索树。

三者均通过当前引导方向测试，但暴露出 v0.1 需要补充的边界。

## 继承 v0.1 的规则

### 1. 根据错误类型选择引导强度

```text
核心状态错 → 给理由 + 聚焦检查
简单操作错 → 短指出 + 轻问题
递归结构错 → 指代码 + 解释实际含义 + 检查返回/状态
用户明确省略 → 放行
```

### 2. 引导要贴当前真实卡点

不要为了套模板，把问题抽象到另一个层级。

### 3. 引导要有理由

不要只说“看这个”，还要说明为什么先看它。

### 4. 避免控制感

少用：

```text
这一轮只检查……
先别管 A，也别管 B……
```

可改为更自然的焦点建议。

## v0.2 新增规则

### 1. 不要直接列出关键边界答案

101 负例：

```text
当 tree_left 和 tree_right 都是 null 时，这一对镜像位置应该成立；
当只有一个是 null 时，结构已经不对称；
当两个都存在时，才需要继续比较值和递归子节点。
```

问题：

- 这是直接给出三种边界情况的答案；
- 对引导来说越界。

更好：

- 指出入口判断是焦点；
- 说明为什么入口判断重要；
- 给一个具体最小案例；
- 让用户自己判断返回含义。

### 2. 递归边界类问题要给具体最小案例

101 通过版：

```text
看这个最小例子：

  1
 / \
2   2

当递归比较完两个 2 之后，会继续比较它们的左/右孩子。
此时两边对应位置都是 null。

这个时候，duic(null, null) 应该表示“这一对匹配完成”，还是表示“不对称”？
```

原则：

- 不直接给答案；
- 但给具体情境；
- 让用户在最小案例上判断。

### 3. 算法范式识别，不急着命名范式

148 通过版：

```text
下一步先看“子问题到底是什么”。

原因是：你已经会找中点，也知道两个有序链表可以合并；卡住的不是单个链表操作，而是没有识别出原问题能变成同类小问题。

如果把 4 -> 2 -> 1 -> 3 从中点拆成：

4 -> 2
1 -> 3

你先别想完整排序过程，只看一个问题：
“把 4 -> 2 排好序”和“把 4 -> 2 -> 1 -> 3 排好序”，是不是同一种问题，只是规模变小了？
```

原则：

- 先让用户看见同构子问题；
- 不急着说“这就是分治”；
- 用具体拆分承载抽象。

### 4. 用户已发现现象但未命名结构时，不急着给术语

98 通过版：

```text
下一步先看“这个额外限制要怎么被带下去”。

原因是：你已经发现 b 不只要和父节点 a 比，还要满足根节点留下的限制。现在真正的问题不是“要不要比较根节点”，而是这个限制怎么一路传到更深的节点。

看这个例子：

     10
    /
   5
    \
     8

当你从 10 走到左子树时，下面所有节点都必须满足“小于 10”。
再从 5 走到右孩子 8 时，8 又必须满足“大于 5”。

先不急着命名这个结构。只看 8：它现在是不是同时被两个限制夹住了？这两个限制分别来自哪里？
```

原则：

- 承接用户已经发现的现象；
- 不直接给最终术语；
- 用具体例子帮助用户看清约束来源。

## 当前分流

```text
递归边界卡点
→ 给最小树/最小调用，让用户判断返回含义

算法范式识别卡点
→ 给具体拆分，让用户判断子问题是否同构

现象已发现但结构未命名
→ 给具体例子，让用户看清来源，不急着命名

简单操作错
→ 短指出 + 轻问题

用户省略低阶细节
→ 放行或轻提醒
```

## 与反馈质量的边界

反馈质量：

- 说明用户当前哪里对、哪里错；
- 不提前给下一步关键答案。

引导方向：

- 给下一步关注点；
- 给理由；
- 给具体情境；
- 让用户自己完成关键判断。

## 未见样本测试结果

### 101 对称二叉树

结果：pass。

修正：

- 不直接列边界答案；
- 给最小树案例；
- 用 `duic(null, null)` 引导用户判断。

### 148 排序链表

结果：pass。

有效点：

- 用具体链表拆分；
- 引导用户看到“排序短链表”和“排序原链表”是同构问题；
- 不急着命名分治。

### 98 验证二叉搜索树

结果：pass。

有效点：

- 不直接给“上下界”；
- 用具体转折路径让用户看到两个限制来源；
- 承接用户已发现的“转折处”。
